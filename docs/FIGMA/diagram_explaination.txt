1. SBI call flow (Sơ đồ trình tự gọi OpenSBI - Trang P4)
Lý thuyết & Luồng hoạt động:

Chuẩn bị tham số (S-mode): Kernel ở Supervisor mode muốn nhờ OpenSBI thực thi một thao tác phần cứng thì sẽ nạp Mã dịch vụ vào thanh ghi $a7 (Extension ID - EID), Mã hàm vào $a6 (Function ID - FID), và các tham số dữ liệu vào từ $a0 đến $a5.

+ 1

Thực thi ecall: Kernel phát lệnh ecall. Lệnh này bẫy CPU, chuyển quyền điều khiển từ S-mode sang M-mode (Machine mode) của OpenSBI.   
image_528679.png
+ 1

Xử lý ở M-mode: OpenSBI Handler tiếp nhận bẫy, kiểm tra cặp EID/FID để gọi đúng hàm xử lý phần cứng bên dưới.   
image_528679.png
+ 1

Thực thi mret: OpenSBI xử lý xong, phát lệnh mret để trả quyền điều khiển về S-mode cho Kernel.   
image_528679.png
+ 1

Nhận kết quả: Kết quả trả về gồm 2 giá trị đóng gói vào cấu trúc struct sbiret: thanh ghi $a0 = sbiret.error (
0 là thành công, khác 
0 là mã lỗi như 
−2: SBI_ERR_NOT_SUPPORTED) và thanh ghi $a1 = sbiret.value.

3. State machine hart (Biểu đồ trạng thái CPU/Hart - Trang P3)
Lý thuyết & Luồng hoạt động:

Mô tả vòng đời quản lý trạng thái của từng nhân CPU (Hart) theo chuẩn SBI HSM Extension (EID 0x48534D).   
image_528679.png
+ 1

Khởi động (STOPPED 
→ START_PENDING 
→ STARTED): Mặc định khi bật máy, các Hart phụ (Hart 1..N) nằm ở trạng thái nghỉ STOPPED. Hart chính (Hart 0) gọi sbi_hart_start(hartid, start_addr, opaque) để chuyển Hart phụ sang START_PENDING. Khi OpenSBI hoàn tất giao quyền ở S-mode, Hart phụ chuyển sang STARTED và chạy mã Kernel (secondary_entry).   
image_528679.png
+ 4

Tạm dừng/Tắt (STARTED 
→ STOP_PENDING/SUSPENDED): Hart có thể dừng (sbi_hart_stop) hoặc đi vào chế độ chờ ngắt tiết kiệm điện (sbi_hart_suspend), sau đó thức dậy lại STARTED khi có ngắt WFI.   
image_528679.png
+ 1

4. Memory map (Bản đồ bộ nhớ - Trang P2)
Lý thuyết & Khớp Thực nghiệm:

0x00000000 - 0x7FFFFFFF: Vùng MMIO cho thiết bị ngoại vi (UART 0x10000000, PLIC 0x0C000000).   
image_528679.png
+ 1

0x80000000 - 0x801FFFFF (2MB đầu RAM): Vùng Reserved dành riêng cho firmware OpenSBI chạy ở M-mode. Phần cứng PMP chặn không cho Kernel ở S-mode can thiệp đè vào.   
image_528679.png
+ 4

0x80200000 (KERNBASE): Địa chỉ nạp Kernel mới. OpenSBI sẽ nhảy tới đây sau khi khởi tạo M-mode xong.   
image_528679.png
+ 2

0x87e00000 (DTB Region): Vùng RAM chứa bảng mô tả phần cứng Device Tree Binary do QEMU tạo ra, địa chỉ này được OpenSBI truyền trực tiếp cho Kernel qua thanh ghi $a1 (đã xác nhận đúng qua log thực nghiệm Task SBI-37).   
image_528679.png
+ 2

end đến 0x88000000 (PHYSTOP): Vùng cấp phát động kalloc cho Page Tables và User Processes.
